# Knowledge Gate：按知识缺口补充（2026-09-10）

## 当前默认：宽松模式（本节优先于下方严格流程）

2026-09-10 联调：在隔离数据中，真实模型已完成首课生成/出题、未通过与通过两种评分、任务/掌握度/目标进度回写和下一课生成。可用 learning:loop:smoke 重现（-- --live 为真实模型），不包含浏览器或联网可靠性验收。评分已提交后下一课失败不回滚当前成绩，接口返回单独提示。

课程结构问题不属于知识门禁：生成器现支持一次字段定向修复、正文常见字段兼容、由实际练习派生考核要求。相关进度与 agent_runs 保存具体字段错误；格式修复后仍经过课程质量与考核流程，不能将规则模板当作真实模型成功输出。

`KNOWLEDGE_GATE_MODE=advisory` 为默认值；无需编辑已有环境文件即可生效。设置 strict 可恢复三轮后阻断。来源验证不足或检索审核异常时，允许模型知识继续教学，显示“模型知识生成 · 未经资料验证”；不伪造引用，也不把模型回答当原文入 RAG。课程内容质量检查仍保留，生成服务失败不会被伪装成成功。

既有 knowledge_unresolved 记录且来源未变化时直接降级，不重复联网。指定教材的 source_required 仍须满足范围约束。来源不足降级时清除历史 groundedContext、来源 ID 和前端引用，防止误标为已验证。手动补充来源后会重新检索。重启 Next.js 生效，无需迁移或重建向量库。

本规则替代此前“自动补充一轮后等待用户选择”及跨操作累计额度方案。

## 当前闭环

1. LLM 规划教学；Tutor 只判断当前动作是否需要外部知识验证，不输出内部思维链。
2. none 不调用检索；需要知识则先执行本地 RAG 与现有 Evidence Review。
3. 证据不足，按 missingTopics 搜索具体知识正文，自动处理最多三个未处理候选。
4. 下载原文 → 现有 ingest/chunk/embedding → 再 RAG/Evidence Review。2026-09-10 起入库前网页用途审核默认关闭（WEB_PAGE_REVIEW_ENABLED=false）；由收录后的 LLM 判断知识是否够用、还需补什么。
5. 充分则立即继续教学；否则仅针对剩余缺口进入下一轮。最多三轮补充后返回 knowledge_unresolved。
6. 用户之后主动重试是新操作，不受上次轮数限制；已保存正文与充分证据可复用。

一次补充操作最多三次搜索和三次补充后 RAG，加上最初一次本地 RAG。单项抓取失败不阻断其他候选；同一操作不重复处理同一 URL。没有可用新正文也需报告原因并验证已有证据，不把搜索摘要当原文。

## 不再自动做的事

不推荐整套书籍、不下载 PDF/Word 附件、不递归展开目录，也不强制用户先勾选教材。用途审核关闭时，不因目录/宣传分类拒绝入库，也不启动基于分类的子页展开；收录只代表抓取文本已保存，不代表适合教学。手动上传、资料范围和手动搜索仍保留。可将 WEB_PAGE_REVIEW_ENABLED 设为 true 恢复旧用途审核及手动目录最多两个同域子页的兼容逻辑。

用户/目标归属、公开地址/SSRF 防护、抓取超时和正文有效性检查仍保留。策略开关纳入知识门禁缓存指纹：切换后重新验证，不沿用旧策略的 knowledge_unresolved 缓存，也不删除旧资料。

source_required 仍受指定教材范围约束，不用全网资料替代用户指定教材。关闭自动联网时请求用户补充，不越过配置。

## 超时与费用边界

不使用历史 rag_count/web_count/page_count 扣额度，不共享 120 秒抓取业务预算。单页保留独立 60 秒及各网络阶段超时；其他服务沿用自身超时。每轮最多处理三个候选，最多三轮，不承诺固定完成时间。成功网页保留原文和出处进入原有资料库，向量化失败仍明确提示现有全文检索降级状态。

## 进度与错误

创建目标和重新生成课堂显示：

- 当前知识补充轮次（1/3、2/3、3/3）及剩余缺口；
- 搜索结果数量、当前来源标题和网址；
- 正文获取、用途审核已跳过（显式启用时显示实际审核）、解析切片入库、向量化；
- 每项成功或失败及具体原因，失败继续其他项；
- 本轮成功数量、重新检索和证据覆盖结果、提前停止或达到上限。

百分比是阶段估计，不是下载字节比例。详细消息由真实服务阶段发送，不包含模型思维链。前端滚动保留最近 100 条记录。默认用途审核阶段记录 skipped，界面不显示“教学正文已确认”；收录后明确由 LLM 判断是否需要下一轮。显式启用审核后，回退仍显示实际 fallbackReason。

## 实现与验证

resolve-knowledge.ts 编排最多三轮；继续复用现有 Web Research 搜索工作流和 web-tools 正文入库，不另建 Agent。web-tools 的 onProgress 报告真实处理阶段。创建与重新生成界面接收原有进度流并保留详细事件。

knowledge:smoke 覆盖三轮终止、第二轮提前成功、缺口变化、自动入库、单项失败、进度消息、充分证据复用和用户独立重试。网页入库、页面用途审核及资料选择界面 smoke 保留兼容测试。外部服务模拟测试不等同真实公网完整教学验收。

启用请重启 Next.js；本次没有数据库结构迁移，也不需要重建向量库。
