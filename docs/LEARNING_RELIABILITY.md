# 学习闭环可靠性：2026-09-12 修复与验收边界

本轮集中处理课程学习闭环的“失败不能假通过”和局部恢复，不新增 Agent、任务队列或另一套证据审核。RAG 宽松门禁策略不变：没有可靠资料时仍可生成明确标注“未经资料验证”的内容，但这不等于允许把审核服务异常算作通过。

## 已实现

1. 正式 Tutor 评分需要完整有效的模型评分。失败返回待评分、可重试，不写入学生成绩；初始诊断评分失败同样不推断能力上下界。
2. 显式演示模式与模型缺配置/连接失败分开；规则评分只允许显式演示课程，页面标注不是实际掌握度。
3. 评分输出以服务端题目 ID、满分及参考答案为准，校验数量、重复/未知 ID、数值、反馈。无答案不得分，0 分不被默认值覆盖。
4. 保存评分时校验当前课节仍可用且内容版本/题目未变化。所有成绩、任务、目标进度和解锁更新仍在原 SQLite 事务内完成。
5. 语义复核无响应、输出损坏或服务故障：保存正文及 `semantic_review_unavailable`，不开放课后考核，也不因此全文修订。
6. 复核重试：读取已保存正文和引用证据，生成新的内容版本标识，仅重新审核；成功才出题。审核发现真实问题时可执行已有的有界修订。旧引用已不可用时明确报错，不伪造证据。
7. 同一套题重复答题不再次提升画像置信度或掌握度，但保留每次成绩与任务通过状态。完成某次练习不等于获得一份新的独立能力证据。
8. 课后答案自动保存到 schema 17 的 `lesson_answer_drafts`，按用户/课节/完整题目指纹隔离；乐观版本控制拒绝不同页面的过期覆盖，相同内容重试幂等。草稿不会写入成绩或掌握度。
9. 页面恢复当前题目版本最近一次成绩和已提交答案；更新草稿不自动更新旧成绩。下一课入口不再因刷新丢失。修复完成数重复追加，以及恢复后的顶部成绩等级。

## 草稿与恢复契约

- `GET /api/learning-drafts?programId=...&lessonId=...`：登录校验与课节归属校验后，返回当前版本草稿、版本号和最近一次匹配题目快照的成绩；不返回未评分题的参考答案。没有草稿但有历史提交时恢复该次答案。
- `PUT /api/learning-drafts`：接收课节、指纹、期望 revision 和答案。只允许当前可答课节的已知题目，每题最多 3000 字符；返回确认后的 revision。未知题目/格式错误 400，未登录 401，越权 404，换题/过期页面 409。
- 前端串行保存并合并保存期间发生的新编辑。保存失败保留页面内文本，可重试或复制；冲突时不自动覆盖远端。提交评分和课节/目标切换前检查是否已保存。
- 页面隐藏/卸载时尽力提交，刷新时对未保存答案提示；**没有离线队列或绝对退出保护**。突然断网、强制关闭前未得到“已保存”确认的内容仍可能丢失。当前不包含初始诊断答题草稿。
- 正式评分故障仍遵守前一阶段的 fail-closed：草稿保存不等于评分成功，不用旧成绩冒充新结果。
- 生效需要重启 Next.js：新连接初始化时创建草稿表，不改写历史课节或成绩，不需要重建资料库。

## 确定性验证

运行 `npm run verify:learning`。当前汇总 16 组本地回归，无真实模型调用，无用户数据库改写。

本轮结果：16/16 通过，schema 17 校验、typecheck、lint 通过，完整生产构建通过（构建子进程使用获准的沙箱外执行）。

- 评分服务 HTTP 503，长篇关键词答案也不能得到正式成绩。
- 缺题、重复 ID、未知 ID、非法分数、满分不匹配和缺反馈输出被拒绝，最多一次格式修复。
- 乱序反馈依题目 ID 对齐，空答案为 0，参考答案不能被模型替换。
- 正式诊断评分异常/非法数字不生成诊断成绩。
- 无来源时语义审核故障也不会通过；缺字段/矛盾通过标记被拒绝。
- 真实业务路由在隔离 SQLite 中评分失败后，成绩数、掌握度、任务、目标进度及下一课锁定状态不变。
- 同题重复通过不增加证据数；旧版本评分提交被拒绝。
- 审核连续失败后仍保留原教学块；恢复后仅审核和出题，不额外 RAG、全文生成或服务故障修订。
- 实际 React 渲染区分待复核、演示结果和内容错误。
- 实际草稿路由与隔离 SQLite 验证保存/恢复、权限、锁定课节、换题、多页面冲突、幂等重试、长度限制和成绩恢复；草稿读写不产生额外答题尝试。
- 实际前端草稿控制器覆盖保存期间继续输入、网络失败再试、冲突后保留文本、拒绝旧题页面，以及浏览器原生 fetch 的接收者绑定。

这是业务逻辑与故障恢复验证，不是评分准确率或教学质量实验。

## 浏览器验收（独立规则演示环境）

用 `scripts/seed-draft-ui-smoke.mjs` 创建临时数据库和测试账号，在独立本地端口启动生产构建，显式设置 `LLM_PROVIDER=rules`、`WORKFLOW_AUTO_WEB=false`；不复用用户数据库。

实际通过：登录→三题输入→看到保存确认→刷新恢复文本和换行→规则评分→刷新恢复分数/反馈/下一课入口→生成第二课→第二课草稿为空、不带入第一课答案→提交后即时完成数为 2/3。第一课恢复后的顶部等级与已保存结果一致。

期间真实发现并修复了浏览器 `fetch` 的 Illegal invocation 和前端完成数重复追加。上述演示评分仅验证状态流转，不用于评价内容、诊断或评分质量；真实模型端到端验收仍独立进行。

## 下一批工作及验收标准

| 工作 | 当前缺口 | 后续验收 |
| --- | --- | --- |
| 后台任务生命周期 | 当前课节生成仍由请求驱动，不能承诺关闭浏览器/重启后自动继续 | 任务 ID 持久化、状态查询、超时/租约、幂等重试；关闭页面和进程重启后恢复同一任务，不重复提交结果 |
| 初始诊断草稿/离线保护 | 课后草稿与刷新恢复已实现；诊断草稿和离线持久队列未实现 | 扩展到诊断会话/题目版本；断网、强制关闭及跨设备冲突单独验证 |
| 真实模型闭环验收 | 本轮有模拟故障、隔离业务测试及规则演示浏览器验收，未重跑真实模型 | 新账号创建目标→诊断→首课→错误答案不通过→有效回答通过→任务/画像回写→下一课；再分别注入模型故障和页面刷新 |
| 能力估计 | 仍为启发式分数与置信度，不是校准的知识追踪；同题订正不直接提升能力值 | 保留独立新题证据，比较错误类型、前后测/迁移题表现，再考虑难度和置信度参数 |
| RAG 效果 | 收录成功不等于检索相关或教学有效，尚无可信效果数据 | 固定目标、查询与标注集，分别统计检索、证据充分性、生成、评分的成功率/耗时/成本；不要用资料条数替代学习效果 |
| 历史入口统一 | 学习记录中的旧 `/api/quiz` 短测和未使用的 legacy 评分导出未在本轮统一 | 明确与课程/初诊评分的边界，后续迁移到同一验证契约；本轮不宣称全部旧入口均已完成改造 |

不得因上述本地回归通过就写“闭环生产可靠”或“学习效果提升某百分比”。也不自动删除、改判历史成绩；若需要清理历史规则成绩，先明确用户、时间范围与保留方案。
