日期：2026-09-15。状态：编码和向量检索入口已接入 LlamaIndex，待用户重启服务并上传文件验收。

## 本轮实施调整（优先于下方原分阶段方案）

用户允许重新向量化、不要求旧向量对照测试，要求保留切片查看。为避免额外存储系统，当前使用 SQLite 作为唯一持久化数据源：Node 筛选授权范围、活动版本及 profile，分批发送最多 128 个预计算向量给 Python；LlamaIndex 建立临时 VectorStoreIndex 并精确检索，Node 合并排序并继续组装证据。不是每次全库重建持久化索引，不重复生成文档向量；但仍有向量传输和临时索引开销，仅适用于当前本地 Demo。

此方案替代原 M1–M4 中必须先做独立持久化索引适配才接入的顺序。尚未实现独立存储适配和关键词检索迁移；FTS5 留作现有降级。没有新增 legacy/llamaindex 开关，升级后的向量入口直接调用 Python；auto 降级仍显式记录原因。RAG 服务不访问数据库、不接受用户资料 ID 读取请求，仅处理业务服务提交的向量快照，因此不能通过伪造 userId 在此服务读取用户库。部署保持本机回环访问；跨主机或公网部署前必须另加服务鉴权。

文档和查询统一调用 LlamaIndex LocalEmbedding 适配器，再由原 GPU 服务编码；原始文本、query instruction 责任与模型不变。切片查看新增实际编码文本展开，不更改父子片段存储接口。

按用户最新要求，跳过真实文件/模型/向量效果对比，仅运行必要代码检查；下方效果验收用例留给用户验收，不标记成已经通过。

遵循 [架构边界](ARCHITECTURE_BOUNDARIES.md)：LangGraph 管跨步骤状态、分支与恢复；Pydantic AI 管节点内部模型调用、受控工具执行与结构化输出。本次只迁移 RAG 内部实现，不迁移 Tutor、不新增 Agent、不修改知识门禁宽松策略。

## 1. 基于当前代码的起点

| 当前入口 | 当前实现 | 迁移方向 |
|---|---|---|
| `lib/knowledge/search-tool.ts` | 注入可信上下文，调用目标范围检索 | 对外契约保留 |
| `lib/db/retrieval.ts` | 范围校验、FTS5/向量选择、SQLite 向量扫描、证据组装与记录 | 保留权限和运行记录，替换内部检索执行 |
| `lib/db/embeddings.ts` | 按片段校验和跳过已有向量，调用本地模型，写入 SQLite | 保留业务事务与幂等，Embedding 和索引操作经 LlamaIndex 适配 |
| Python `growth_loop_rag/chunking.py` | 已使用 LlamaIndex 父子切片 | 初期保留切片参数，不同时改变检索实验变量 |
| `lib/knowledge/embedding-client.ts` | 调用本地 `/v1/embeddings` | Python 侧增加同契约的 LlamaIndex Embedding 适配器 |

现有 RAG Python 服务固定 `llama-index-core==0.14.24`。实施时先检查安装版本的接口，不顺带升级依赖。MinerU 解析和本地 Embedding 模型进程继续保留。

## 2. 不变的调用方契约

`searchKnowledgeBaseTool(context, input)` 保持不变：

- 可信 context：用户、目标、课节、能力、用途、工作流幂等键；从会话/工作流注入。
- 查询 input：query、mode、model、topK、maxEvidenceTokens。运行时只读取允许字段，不能仅依靠 TypeScript 类型阻止身份字段覆盖。
- 输出：保留现有 EvidenceBundle，包括返回片段、来源和检索运行标识、证据状态。以实际类型为准，不另造一个只返回字符串的接口。
- 返回候选必须二次核验：属于授权范围、活动片段版本、选定模型 profile；未知 ID、重复 ID、非有限分数均拒绝或显式处理。

Agent 不直接传任意数据库路径、用户 ID、文件路径或索引命名空间。课程生成和课堂提问使用同一入口，但保留各自 topK 与证据预算。

## 3. 目标执行链路

```text
上传/联网资料 → 原有解析入口 → MinerU 或文本解析
  → LlamaIndex 父子节点 → 业务服务保存不可变片段与来源
  → LlamaIndex Embedding/索引适配 → 原有本地 Embedding 服务
  → 经业务服务校验并持久化向量

RAG Tool → 业务服务鉴权、解析目标范围与活动版本
  → LlamaIndex Retriever + 索引适配
  → 同模型 query embedding → 范围内候选
  → 原有父片段补充、证据预算、Evidence Review 与 RetrievalRun
  → 带来源的 EvidenceBundle → Tutor
```

不启用 LlamaIndex 回答生成器；不让它另外控制联网补充、用户确认或教学恢复。匹配片段不等于教学证据充分，原有 Evidence Review 保留，不新建第二套。

## 4. 存储与权限方案

第一阶段不引入新的向量数据库，也不清空 SQLite。现有 `source_chunk_embeddings`、资料版本、片段 ID 与父子关系是兼容基线。

LlamaIndex 使用存储适配层访问已有向量，而不是每次检索把整个用户库传给 Python、临时重建完整索引。可先用授权快照的少量测试数据验证适配，但不能把测试原型当作最终持久化索引方案。

生产接入需满足：

- 业务服务解析并授权范围，内部服务请求必须认证；不能因为运行在本机就允许调用者任意指定用户身份。
- Python 不直接写学习业务表；索引读写通过受控存储接口，输入绑定用户、来源版本、chunkSet 和 profile。
- 全局 topK 后再过滤用户不可接受：必须先限定用户/目标范围再排序，否则既有泄露风险也会损失召回。
- 写入结果先验证 chunk ID、输入文本校验和及 profile，再提交。重复批次可幂等复用；旧版本写入不能覆盖新活动版本。
- 初版仍可使用精确向量检索，不宣称接入框架就获得近似索引或性能提升。后续扩容独立评测。
- FTS5 可以作为 LlamaIndex 检索适配器的关键词后端，不必为迁移更换分词或评分算法。最终由统一检索执行入口协调，而不是留两套隐式路由。

## 5. Embedding 一致性与旧向量复用

默认模型沿用共享配置 `EMBEDDING_MODEL`（默认 Qwen3-Embedding-0.6B）；显式 BGE 比较仍允许，但必须独立 profile。

复用前逐项核对：模型标识、revision、维度、归一化、文档上下文前缀模板、query instruction，以及实际输入文本校验和。两模型虽然均为 1024 维，也不能互相比较。

适配器必须分别实现 document/query 编码；不要让 LlamaIndex 再自动追加一遍现有服务已经应用的 query instruction 或 metadata 前缀。不使用框架隐式默认的云端 Embedding/LLM。

完全一致的已有向量直接复用。只有旧 BGE 索引的来源不能冒充已经有 Qwen 索引：显式 vector 返回未就绪；auto 允许明确记录关键词降级。需要补建时单独显示来源清单与预计工作量，不在一次查询中悄悄全库重算。

## 6. 分阶段实施与切换

1. **M0：基线与契约**。固定隔离测试库、相同查询和当前候选分数/来源；不改变用户库。记录现有 FTS5、向量和空结果行为。
2. **M1：Python 适配器**。接入现有本地 Embedding HTTP 协议，测试 document/query、模型契约、批量计时、失败和超时；用 LlamaIndex 节点与检索接口验证已有向量复用。
3. **M2：存储与内部服务**。实现受认证的范围索引访问和幂等写入；加入版本一致性与结果 ID 校验，再接入持久化检索。
4. **M3：业务接入**。RAG Tool 内部切到新后端，目标范围检索与单资料检索均覆盖；返回 EvidenceBundle 的组装、审核及数据库记录不变。
5. **M4：对照与启用**。完成下表回归和一轮真实本地 Embedding 查询后再切默认。记录实际测试结果，不将模拟向量结果视为召回率评测。

迁移期间可增加显式 `RAG_RETRIEVAL_BACKEND=legacy|llamaindex` 切换（尚未实现）。同一请求只使用一种执行后端；不做隐藏双写或自动改回 legacy。模型/权限/版本契约失败必须报错；原有 auto 模式允许的关键词降级须记录原因。

回滚只切执行入口，不删除数据。旧路径在验收后再移除；不得以“迁移中”为由长期保留两套默认入口。

## 7. 验收条件

| 用例 | 必须满足 |
|---|---|
| document/query 编码 | 同一 profile；前缀恰好应用一次 |
| 已有兼容向量 | 无重复 Embedding 请求，来源 ID 不变 |
| BGE/Qwen 混存 | 只比较选定 profile；不按相同维度混算 |
| 授权范围 | 用户 A 不能取 B 的片段；目标排除资料不参与排序 |
| 活动版本切换 | 不返回旧活动片段；并发变更明确重试或拒绝，不混合版本 |
| 参数与返回值校验 | 身份覆盖、未知 ID、非法分数和损坏向量不能静默通过 |
| 重复入库/恢复 | 不重复增加活动索引；失败批次可单独重试 |
| 父子召回 | 命中子片段保留定位和父 ID；补充上下文不突破权限和证据预算 |
| auto/vector/fts5 | 语义与现有接口一致；降级原因可见 |
| 服务离线/超时 | 返回具体失败阶段，不误报资料足够，不隐式切模型 |
| 课程与课堂提问 | 两入口都能取得同一契约的来源证据 |
| 计时 | 编码、索引写入、查询编码、检索、证据处理分别记录，区分冷加载与实际编码 |

基线精确向量排序使用相同固定向量对照，分数按浮点容差比较；分数相同不强制要求不稳定的 ID 顺序。FTS5 不更改算法时对照相同命中。真实教学相关性另做标注数据评测，不在本次虚构效果提升。

接入后执行：Python 单元/服务契约测试、现有 RAG Tool 回归、学习回归、typecheck、lint、build。真实测试只使用隔离资料和明确授权的模型调用，不修改用户历史课程。
